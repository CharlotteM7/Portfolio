Objective, clue and puzzle system

Cryptography Puzzle Game · UE5 C++ exposed to Blueprints · Project page

Problem

The game needed a chain of objectives where each step might need a clue found, a cipher solved, or both, and the notebook UI had to show the right notes at each step. I wanted to add and reorder puzzles in the editor without new code.

Design

  • FObjective is a Blueprint-visible struct: title, description, the clue ID and puzzle tag it needs, and notes shown before and after it's solved.
  • UObjectiveManager is an actor component holding the ordered list and the current index. Designers edit the list in the Details panel.
  • AClue and AACipherPuzzleActor don't know about each other. They call into the manager, which broadcasts OnObjectiveUpdated and OnClueFound.
  • The notebook widget listens to those delegates, so UI updates are event-driven rather than polled every tick.

Key code

void UObjectiveManager::NotifyPuzzleSolved(int32 Index)
{
    // Validate the incoming Index, not the current one
    if (!Objectives.IsValidIndex(Index))
        return;

    FObjective& Obj = Objectives[Index];
    if (!Obj.bIsComplete)
    {
        Obj.bIsComplete = true;
        CurrentObjectiveIndex = FMath::Clamp(Index + 1, 0, Objectives.Num() - 1);

        // Broadcast so the notebook pulls in the next NotesBefore/After
        OnObjectiveUpdated.Broadcast(CurrentObjectiveIndex);
    }
}

Runtime terrain generation and streaming

Runtime Procedural Terrain · UE5 C++ · Project page

Problem

Generate terrain around the player at runtime, far enough to feel open, without frame spikes when new ground is built.

Design

  • Height is four octaves of Perlin noise (mountains, land and two detail layers), with a flat spawn circle that lerps into the noise.
  • The world is a grid of tiles. QueuedTiles maps each grid coordinate to its mesh section and LOD level.
  • Tiles are generated in an FAsyncTask on a background thread. The LOD level divides the vertex count, so distant tiles are cheap.
  • As the player moves, RemoveLODQueue swaps outdated tiles for ones at the right detail level.
  • Foliage uses instanced static meshes, a seeded FRandomStream and slope checks, so a saved seed rebuilds the same world.

Key code

float AWorldGenerator::GetHeight(FVector2D Location)
{
    float DistFromCenter = FVector2D::Distance(Location, FVector2D(0, 0));

    if (DistFromCenter <= FlatRadius)
        return FlatHeight; // Inside the central flat area

    float ProceduralHeight = CalculateProceduralHeight(Location);

    if (DistFromCenter <= TransitionEndRadius)
    {
        // Transition zone
        float TransitionFactor = (DistFromCenter - FlatRadius) / TransitionWidth;
        return FMath::Lerp(FlatHeight, ProceduralHeight, TransitionFactor);
    }
    return ProceduralHeight;
}

Networked three-player Pong

Multiplayer Pong · C++ / SDL2 client, Java server · Project page

Problem

Extend a two-player client and server into a three-player game with a power-up, keeping the server in charge of game state.

Design

  • The client only sends input as key up/down messages, one pair per player.
  • The server simulates the match and sends GAME_DATA and SCORES messages. The client parses them into a single GameData struct each frame.
  • Power-up position and state ride along in GAME_DATA, so every client sees the same pickup.
  • Purely visual feedback (particles, sounds, pause menu) stays on the client.
