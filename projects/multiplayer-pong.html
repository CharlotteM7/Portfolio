Overview

I took the module's basic two-player client and server and turned them into a three-player game. A third, horizontal bat guards the bottom of the screen, and a power-up spawns in the middle of the court. The server runs the simulation and sends state to the client, which renders it in SDL2 with particles, sound effects, a pause menu and a win screen.

What I added

  • Third player with a horizontal bat, and per-player scoring.
  • Power-up pickup synced from the server.
  • Client-side particles, sound effects and bat textures.
  • Pause menu with a controls screen, and a win screen.

Networked three-player Pong

How it's built · C++ / SDL2 client, Java server

Problem

Extend a two-player client and server into a three-player game with a power-up, keeping the server in charge of game state.

Design

  • The client only sends input as key up/down messages, one pair per player.
  • The server simulates the match and sends GAME_DATA and SCORES messages. The client parses them into a single GameData struct each frame.
  • Power-up position and state ride along in GAME_DATA, so every client sees the same pickup.
  • Purely visual feedback (particles, sounds, pause menu) stays on the client.
