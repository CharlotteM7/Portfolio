Runtime Procedural Terrain

  • Role: Solo developer
  • Context: BSc Computer Science for Games dissertation
  • Engine: Unreal Engine 5
  • Tech: C++, Procedural Mesh Component, Instanced Static Meshes
  • Platform: PC
Code on GitHub Dissertation (PDF)

Overview

A terrain system that generates and streams the world around the player at runtime. Height comes from four layered octaves of Perlin noise, with a flat, safe spawn area that blends into the landscape. The world is split into tiles that are generated on a background thread, rebuilt at lower detail as the player moves away, and dressed with foliage that respects slope. Players can save and reload a terrain layout, and the navmesh rebuilds so AI can move across new ground.

What I built

  • Mesh generation: vertices, triangles, UVs, normals and tangents per tile.
  • Tile streaming around the player with a distance-based LOD queue.
  • Async generation so new tiles don't stall the game thread.
  • Seeded foliage scattering with slope checks, using instanced meshes.
  • Save/load of terrain settings, and runtime navmesh rebuilds.
  • Height and scale settings exposed in the editor, so the look of the world can be tuned without touching code.

Code and systems

The generator owns a queue of tiles keyed by grid coordinate. Each tile is generated off the game thread at a detail level set by its distance from the player.
