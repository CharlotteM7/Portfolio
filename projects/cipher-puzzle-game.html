Overview

A third-person detective game that teaches substitution ciphers. Players explore a scene, collect clues and decode messages to progress, with a notebook that updates as they learn. I wanted the teaching to happen through play rather than tutorials, so every cipher is tied to an objective and a place in the level. Hints scale with the player, keeping it approachable for beginners. I playtested it with five players, and all five gave positive results on enjoyment and learning.

My role

  • Designed the puzzle progression, level layout and narrative framing.
  • Wrote the objective, clue and cipher-puzzle systems in C++, exposed to Blueprints.
  • Built the notebook UI that pulls notes from the current objective.
  • Designed the hint system and ran user testing.

Objective, clue and puzzle system

How it's built · UE5 C++ exposed to Blueprints

Problem

The game needed a chain of objectives where each step might need a clue found, a cipher solved, or both, and the notebook UI had to show the right notes at each step. I wanted to add and reorder puzzles in the editor without new code.

Design

  • FObjective is a Blueprint-visible struct: title, description, the clue ID and puzzle tag it needs, and notes shown before and after it's solved.
  • UObjectiveManager is an actor component holding the ordered list and the current index. Designers edit the list in the Details panel.
  • AClue and AACipherPuzzleActor don't know about each other. They call into the manager, which broadcasts OnObjectiveUpdated and OnClueFound.
  • The notebook widget listens to those delegates, so UI updates are event-driven rather than polled every tick.

Key code

void UObjectiveManager::NotifyPuzzleSolved(int32 Index)
{
    // Validate the incoming Index, not the current one
    if (!Objectives.IsValidIndex(Index))
        return;

    FObjective& Obj = Objectives[Index];
    if (!Obj.bIsComplete)
    {
        Obj.bIsComplete = true;
        CurrentObjectiveIndex = FMath::Clamp(Index + 1, 0, Objectives.Num() - 1);

        // Broadcast so the notebook pulls in the next NotesBefore/After
        OnObjectiveUpdated.Broadcast(CurrentObjectiveIndex);
    }
}
